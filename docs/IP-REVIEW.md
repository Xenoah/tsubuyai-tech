## 著作権・取得条件

文化庁は、事実・データ・アイデア等と創作的表現を区別し、他の権利・法令・利用条件にも注意が必要と説明している。
これを踏まえ、元記事の複製を集める方式を採らず、短い独自見出し・要約、URL、発信者、日付、確認メモだけを保存する。
文字数制限や出典表記そのものが免責条件にはならない。翻訳・近似言い換え、詳細すぎる要約、創作的な図表の再現は避ける。
本文・写真・ロゴ・OGP・スクリーンショット・原文引用は公開データスキーマで受け付けない。
UIのSVGはコードから独自作成した装飾であり、報道写真や科学的な証拠図ではない。
プレスリリースが公開されていることを、画像や本文の自由転載許可と解釈しない。
取得時の規約・robots・アクセス制限も更新担当が確認する。現実装は自動スクレイピングを行わない。

参照: https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/chosakukensha_fumei/

## 特許の検討範囲

特許の技術的範囲は特許請求の範囲等に基づき判断される。外観変更や独自に実装したことだけで非侵害にはならない。
均等論もあるため、一部の構成を変えただけで回避が成立するとは限らない。
本作業で行ったのは一般原則の確認と実装構成の記録であり、網羅的なFTO（他者の権利を侵害せず実施できるかの調査）ではない。
特定の特許請求項に対する非充足判定、法的意見、全世界の権利クリアランスは未実施。

参照:
- 特許庁「特許請求の範囲の記載要件」 https://www.jpo.go.jp/system/laws/rule/guideline/patent/tukujitu_kijun/ht/02_0200.html
- 特許庁「特許権の均等論」 https://www.jpo.go.jp/support/ipr/qanda/q04.html
- 特許法 第70条・第71条 https://laws.e-gov.go.jp/law/334AC0000000121
- J-PlatPat https://www.j-platpat.inpit.go.jp/

## 実装した構成と判断

| 機能 | 今回の実装 | 判断の限界 |
| --- | --- | --- |
| タイムライン | JSONを発表日で単純に並べ替え、12件ずつ表示 | 一般的な構成でも特許の非侵害を保証しない |
| キャラ別表示 | author IDを条件として抽出 | 個別クレームとの照合は未実施 |
| 保存・購読 | localStorage内のIDリスト、サーバーへの送信なし | ソーシャルグラフ、人気度推定、レコメンドを実装しない |
| 新着の検知 | 同一サイトの小さなmanifestを120秒ごとに確認 | 新着通知方式を特定特許と比較したわけではない |
| アニメーション | SVG形状、CSS transform/opacity、可視領域で停止 | 第三者の動画・演出ソースを転用しない |
| ニュース編集 | 外部のGPTがMarkdownを読み、人が追える根拠付きデータをpush | 真偽・著作権の自動的な法律判定ではない |

## 意匠・商標・表示

Xのロゴ、名称、配色、独自資産、既存キャラクター、ソースコードを使わない。サービスの関係者や公式サービスを名乗らない。
サービス名は「つぶやいテック」。商標・名称の包括的なクリアランスは未実施。商用展開・広告投入の前に名称・ロゴを対象地域で確認する。
画面の見た目についても、著作権とは別に意匠や不正競争の観点がありうるため、完全な免責を主張しない。

## 本格運用前に行う調査

1. 対象国、提供主体、商用・非商用の範囲、実装バージョンを確定する。
2. タイムライン生成、購読、更新通知、分類・記事選別等を構成要件に分解する。
3. J-PlatPat等で関連する存続中の特許・公開出願・意匠を調査し、権利者、優先日、法的状態を確認する。
4. 要注意権利を請求項単位で照合し、必要なら弁理士等にFTO評価・設計変更の妥当性を依頼する。
5. 調査記録と設計変更を残し、追加機能・対象国変更時に再調査する。

一般的な機能を中心に構成したことと、特許を侵害しないと確認できたことは区別する。
