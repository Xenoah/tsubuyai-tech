# 2026-11-12 プロフィール拡充とヒカリの許可ドメイン追加

利用者の明示依頼により、全編集キャラクターのプロフィール（bioとmotto）を拡充し、ヒカリの許可ドメインにhuggingface.coを追加した。担当分野・新着期間・文字数上限・一次資料確認・著作権等の条件は維持する。変更はプロフィールの表示文と、ヒカリが一次資料として使える範囲の拡大のみである。

移行元: [e11d9e2cbe2518fbf5f469e4ee63d02300d5dd7c](https://github.com/Xenoah/tsubuyai-tech/tree/e11d9e2cbe2518fbf5f469e4ee63d02300d5dd7c)。この版の全23記事を読み込み、記事本文・レビューを変更していないことを比較した。今回、ニュースの一次資料を再調査したとは扱わない。

## 既存レビューを偽らないための限定保持

[content/review-preservation.json](../content/review-preservation.json) に移行時の新しい共通方針・各担当規則のSHA-256と、移行元の23記事の指紋を固定する。指紋は `JSON.stringify({meta: post.meta, body: post.body})` のUTF-8 SHA-256。記事の全メタデータと独自本文を対象とする。

検証では、現在の共通方針・該当担当規則・記事ID・記事指紋がこの台帳とすべて一致する場合だけ、当時のreview.policyHashとreview.agentRuleHashを保持できる。それ以外のすべての公開ゲートは現在の規則で実行する。記事のハッシュやreviewedAtを新しく確認したように書き換えていない。

- 本文、出典、時刻、レビュー、IDなどを変更したら保持対象外。現在の規則を実際に読み、必要な出典再確認とレビューを行う。
- 新規記事では現在のルールハッシュが必須。今回の台帳に追記して通さない。
- 共通方針または担当規則をさらに変えた場合も保持対象外。将来の方針変更を自動的に承認しない。
- 通常のニュース更新で台帳を編集しない。台帳の拡張はこの移行の目的に含まれない。

これは新しい事実確認を記録する処理ではなく、プロフィール文と出典範囲の変更によって既存の正直な確認記録を失わないための互換処理である。
