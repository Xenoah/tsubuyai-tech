# 2026-10-15 文字数ルールの移行

利用者の明示依頼により本文の上限を240文字から2000文字へ拡張し、300文字を超える本文を折りたたむ。EDITORIAL.mdでは上限と冒頭の留意点の扱いを変更し、agents/*.mdではmaxSummaryCharsのみ変更した。担当分野・許可ドメイン・一次確認・新着期間・著作権等の条件は維持する。

移行元: [e9f56ce633d7af222265c6f198498dab77deec1f](https://github.com/Xenoah/tsubuyai-tech/tree/e9f56ce633d7af222265c6f198498dab77deec1f)。この版の全11記事を読み込み、旧240文字制限に収まっていること、記事本文・レビューを変更していないことを比較した。今回、ニュースの一次資料を再調査したとは扱わない。

## 既存レビューを偽らないための限定保持

[content/review-preservation.json](../content/review-preservation.json) に移行時の新しい共通方針・各担当規則のSHA-256と、移行元の11記事の指紋を固定する。指紋は `JSON.stringify({meta: post.meta, body: post.body})` のUTF-8 SHA-256。記事の全メタデータと独自本文を対象とする。

検証では、現在の共通方針・該当担当規則・記事ID・記事指紋がこの台帳とすべて一致する場合だけ、当時のreview.policyHashとreview.agentRuleHashを保持できる。それ以外のすべての公開ゲートは現在の規則で実行する。記事のハッシュやreviewedAtを新しく確認したように書き換えていない。

- 本文、出典、時刻、レビュー、IDなどを変更したら保持対象外。現在の規則を実際に読み、必要な出典再確認とレビューを行う。
- 新規記事では現在のルールハッシュが必須。今回の台帳に追記して通さない。
- 共通方針または担当規則をさらに変えた場合も保持対象外。将来の方針変更を自動的に承認しない。
- 通常のニュース更新で台帳を編集しない。台帳の拡張はこの移行の目的に含まれない。

これは新しい事実確認を記録する処理ではなく、文字数ルールの変更によって既存の正直な確認記録を失わないための互換処理である。
