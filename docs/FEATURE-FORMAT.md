# 長文記事（ブログ形式）の形式

長文記事は、SNS風ポスト（`content/posts/`）の詳細版です。ポストに「長文版で読む」リンクが付き、長文タブ（`#/features`）に一覧が並びます。ファイルは `content/features/` に置き、ポストと同じ包み（1行目が見出し、次の ```json ブロックがメタ情報、残りが本文）を使います。

## メタ情報

ポストの全フィールドに、次の1件を加えたものが長文記事のメタ情報です。

- `postId`（必須）: 詳細版となるSNSポストのID。担当者はポストと同じキャラクターでなければならず、1ポストにつき長文は1本までです。ポストより前に公開することはできません。

その他のフィールド（id、author、category、headline、publishedAt、sourceDate、eventDate、tags、status、kind、sources、review、corrections、annotation）の意味と検証はポストと同一です。出典は担当キャラクターの許可ドメイン内から選び、一次資料を最低1件含めます。レビューの `policyHash` と `agentRuleHash` は現在のルールのハッシュと一致しなければならず、保存（review-preservation）の対象にはなりません。

## 本文

- 独自文のプレーンテキストのみ。段落は空行で区切ります。
- 文字数は800〜12,000文字（Unicodeコードポイント）。
- URL、画像、コード、見出し記号、HTMLは書けません。出典へのリンクは画面が自動で付けます。
- 一次資料の主張は「発表した」など帰属を明確にし、メーカー測定と独立検証を区別します。重要な条件や制限は省略しません。

## 公開

ポストと同じ公開ゲートを通ります（`npm test` と `npm run build`）。長文だけを追加・訂正する場合も、リモートの最新状態を確認してから反映し、公開後に配信データと実ページで確認します。
